# Raven — правила для агентів (Codex, Claude Code та інші)

Перед будь-якою задачею прочитай [RAVEN_CONTEXT.md](RAVEN_CONTEXT.md) (розділ «Передача
роботи» — актуальний стан, наступні задачі, пастки) і в [CLAUDE.md](CLAUDE.md) розділи
«Safety contracts», «Приватність і дозволи», «Перевірки» та «Паралельна робота з Codex»:
вони обов'язкові для будь-якого агента. Конкретне завдання визначає користувач;
список задач у контексті — рекомендації, не доручення. Не запускай live Raven,
мікрофон, живі API, commit/push без явного дозволу користувача.
Якщо є локальний файл docs/MODEL_SELECTION.md (не в Git, може бути відсутній), звір з ним
вибір моделі перед великою задачею.

# Ведення документації Raven

Після суттєвої зміни коду, архітектурного рішення або експерименту:

- Додати запис у `docs/DEVELOPMENT_LOG.md` за шаблоном із `docs/DEVELOPMENT_RULES.md`.
  Відрізняти дату події від дати запису; невідомі дати не вигадувати.
- Вказати проблему, мотив рішення, змінені компоненти, фактичну перевірку,
  результат і обмеження. Попередню невдачу не переписувати як успіх.
- За зміни стану можливостей оновити `docs/ASSISTANT_ROADMAP.md` та відповідні
  інструкції. Заплановане не позначати реалізованим.
- Для нових збережених доказів додати ID у `docs/EVIDENCE_REGISTER.md` і
  розмір/SHA-256 у `docs/evidence/manifest.json`. Не замінювати старі суми мовчки.
- Розрізняти підставні тести, синтетичне аудіо, живий API й користувацький тест.
  Старий прогін не оголошувати новим; для документаційної зміни вказувати
  перевірку посилань/маніфесту, а не вигаданий прогін застосунку.
- Використовувати `tester.py` як єдину точку входу перевірок застосунку.
  Не запускати платні/живі перевірки лише заради заповнення журналу.
- Не копіювати секрети або приватні діалоги в документацію. Зберігати
  посилання на приватні докази окремо від знеособлених матеріалів публікації.

Ці правила застосовуються в межах поточного завдання; запит лише на пояснення
або рев'ю сам по собі не вимагає змінювати файли чи запускати експерименти.
