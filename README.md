# ValleRa — українськомовний асистент

ValleRa — співрозмовник із локальним розпізнаванням голосу, текстовим чатом
і підтримуваними діями на комп’ютері. Можна спілкуватися природно, попросити
знайти інформацію або файл, відкрити програму чи підготувати робоче місце.

**Статус:** проєкт активно розробляється. Windows — основна перевірена платформа.
На Raspberry Pi/Linux працює текстове ядро та частина локальних дій;
повний голосовий режим ще не готовий. Це не довільний автономний виконавець.

> Локальний інтерфейс не означає повністю офлайн-роботу: текст розмови
> надсилається налаштованому LLM-провайдеру. API може мати плату та ліміти.

## 1. Можливості й обмеження

| Можливість | Що очікувати |
| --- | --- |
| Розмова українською | Текстовий чат через налаштований LLM; на Windows також голос |
| Вебпошук і погода | Підсумки з джерелами; сайти з антибот-захистом можуть бути недоступні, факти варто перевіряти |
| Програми й файли | Відкриття налаштованих програм, пошук файлів у дозволених місцях, вибір результату |
| Робоче місце | Збережений сценарій запуску програм із погодженням; доступний на Windows |
| Керування вікнами | Підтримувані операції з вікнами Windows, а не універсальне керування будь-яким UI |
| Пам’ять, нотатки, нагадування | Збереження контексту та локальних даних; частина функцій викликається точними командами |
| Вебінтерфейс | Чат, стан мікрофона, підтвердження, картка підтримуваного покрокового завдання |
| Діагностика | Перевірка конфігурації, моделей і доступності компонентів |

Важливі межі:

- Розмова **покрокова**, не full duplex: під час озвучення ValleRa не слухає
  себе; голосове перебивання ще не підтримується.
- LLM пропонує лише підтримувані дії. Локальні перевірки й підтвердження
  не замінюються вільним виконанням згенерованого коду.
- Швидкість залежить від комп’ютера, STT-моделі, мережі й LLM API.
  Автоматизовані тести не гарантують якість живого розпізнавання.
- Linux TTS не реалізовано; edge STT залишається експериментальним кандидатом,
  а не готовою голосовою конфігурацією для Pi.
- Додатковий режим «Душогуб» призначений лише для авторизованого аудиту.
  Він не потрібен для звичайної розмови; [умови та команди](docs/USER_GUIDE.md#режим-авторизованого-аудиту-душогуб).

## 2. Що потрібно для запуску

Для Windows орієнтир — **Windows x64 і Python 3.12 x64**, Git та окреме
віртуальне середовище Python. Для голосу потрібні мікрофон, аудіовихід,
локальні STT-моделі й установлений український SAPI-голос, наприклад RHVoice.

Для розмови потрібен хоча б один налаштований LLM: Gemini, Groq, OpenAI,
Anthropic або окремо підготовлений Ollama. Не потрібно мати ключі до всіх.
Без доступної моделі спілкування недоступне; локальні підтримувані команди
не обов’язково потребують API.

Інтернет потрібен для початкового встановлення пакетів/моделей, вебпошуку
та хмарного LLM. Пакети, STT-моделі й TTS-голос — **три окремі складові**:
встановлення Python-залежностей не готує голос автоматично.

## 3. Встановлення на Windows

Відкрийте PowerShell у каталозі для проєктів:

```powershell
git clone https://github.com/Wuradzi/ValleRa.git
cd ValleRa
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe install.py --profile desktop
```

Потім виконайте [повну інструкцію встановлення Windows](docs/WINDOWS_SETUP.md):

1. Установіть український **SAPI-голос** для озвучення, не NVDA-addon.
2. Виберіть STT-профіль у локальному `config.json`, не перезаписуючи старі налаштування.
3. Явно завантажте потрібні моделі — primary STT і Vosk для підтверджень.
4. Запустіть майстер, укажіть пристрої, API-ключ і майстер-пароль:

```powershell
.\.venv\Scripts\python.exe main.py --setup --web-ui
```

Майстер працює **в терміналі** й після налаштування продовжує запуск.
У вебінтерфейсі мікрофон початково вимкнений — увімкніть його кнопкою,
коли STT готовий. Для першої перевірки розмови без STT можна додати
`--text-only`; це вимикає голосове введення, але не обов’язково озвучення.

## 4. Raspberry Pi та Linux

Почніть з [окремої інструкції Linux/ARM64](docs/LINUX_RUNTIME.md):
вона містить системні передумови, встановлення, обмеження і hardware checklist.

На користувацькому Pi вже перевіряли текстове ядро, розмову через Gemini
та виявлення/калібрування мікрофона. Це **не перевірка повного голосового циклу**.

- Для першого запуску використовуйте текстовий режим.
- Не переносіть Windows `.venv`, індекси пристроїв або шляхи дисків.
- Вікна, робоче місце та системні дії Windows не стають автоматично доступними на Linux.
- STT/TTS-переможців для Pi ще не обрано. Нова [benchmark-інфраструктура](docs/STT_BACKENDS.md)
  готує вимірювання, але сама не встановлює моделі й не вмикає Linux TTS.

## 5. Щоденний запуск та інтерфейс

Команди нижче виконуються з кореня репозиторію після встановлення:

| Мета | Команда для Windows |
| --- | --- |
| Чат у браузері | `.\.venv\Scripts\python.exe main.py --web-ui` |
| Консольний режим | `.\.venv\Scripts\python.exe main.py` |
| Вебчат без голосового введення | `.\.venv\Scripts\python.exe main.py --text-only --web-ui` |
| Повторне налаштування | `.\.venv\Scripts\python.exe main.py --setup` |
| Перевірка системи | `.\.venv\Scripts\python.exe main.py --doctor` |
| Стан моделей | `.\.venv\Scripts\python.exe main.py --models` |

Пароль вводиться в терміналі. Браузер відкривається автоматично; з
`--no-browser` посилання буде лише в терміналі.

У вебінтерфейсі:

- **Мікрофон** — дозволяє або вимикає захоплення на комп’ютері з ValleRa.
- **Зупинити відповідь** — зупиняє підтримувану генерацію/озвучення;
  це не універсальне скасування вже виконаних дій.
- **Історія** — показує попередні репліки поточної UI-сесії.
- **Картка завдання** — показує кроки й стан підтримуваного сценарію.
- **Меню «···»** — стан сесії, пауза діалогу й світлові ефекти.

Щоб завершити ValleRa, натисніть **Ctrl+C у терміналі**.
Закриття вкладки браузера не завершує програму й не вимикає мікрофон.
[Докладніше про інтерфейс](docs/USER_GUIDE.md#локальний-вебінтерфейс).

## 6. Як розмовляти й давати завдання

Слово активації «Валера» не потрібне. Почніть, наприклад, так:

```text
Привіт! Поясни простими словами, що таке нейромережа.
Розкажи докладніше.
Відкрий Telegram.
Знайди в інтернеті офіційний сайт Raspberry Pi.
```

За ввімкненого `commands.natural_actions` підтримувані прохання розбираються
без префікса. Неоднозначне прохання може викликати уточнення. Якщо з’явився
запит підтвердження, перевірте дію й ціль, тоді скажіть «так» або «ні» чи
скористайтеся кнопками UI. Відповідь має стосуватися поточного запиту.

Для явної команди й доступу до інших навичок залишається формат:

```text
Команда: список команд
Команда: режим робота
Команда: налаштуй робоче місце: браузер, VS Code, Telegram
Команда: статус завдання
Команда: погода в місті Луцьк
Команда: нова розмова
```

Список можливостей залежить від платформи й завантажених навичок.
«Режим робота» запускає збережений сценарій, а не необмежений агентний режим.
[Докладні сценарії, уточнення та команди](docs/USER_GUIDE.md).

## 7. Налаштування

| Де | Що зберігається |
| --- | --- |
| `config.example.json` | Приклад конфігурації без особистих даних |
| `config.json` | Ваші локальні параметри, пристрої, профілі |
| `.env` | Локальні API-ключі, введені під час налаштування |
| `data/` | Історія, пам’ять, локальні дані й зашифроване сховище секретів |
| `models/`, `cache/` | Моделі й робочий кеш |
| `logs/sessions/` | Журнали окремих запусків |

Не плутайте три різні профілі:

- `install.py --profile …` обирає набір встановлюваних залежностей.
- `stt.profile` обирає конфігурацію розпізнавання: `auto`, `quality`, `balanced`, `edge`.
- `performance.profile` / `main.py --profile …` змінює runtime-параметри;
  це не гарантія меншої STT-моделі.

[Налаштування, журнали й LLM fallback](docs/CONFIGURATION.md) ·
[Моделі, hardware-профілі та обмеження STT](docs/STT_BACKENDS.md).

## 8. Якщо щось не працює

| Симптом | З чого почати |
| --- | --- |
| Мікрофон не реагує | Кнопка мікрофона UI, дозвіл ОС, вибраний пристрій, готовність STT |
| Немає озвучення | На Windows — SAPI-голос, гучність і output device; на Linux TTS ще відсутній |
| Модель не знайдена | Перевірте `--models`, STT-профіль і явне завантаження потрібних ваг |
| Дуже повільне розпізнавання | Перевірте фактичний CPU/CUDA та fallback у журналі; large-v3 на CPU може бути повільною |
| LLM недоступний або 429 | API-ключ, доступ до вибраної моделі, мережа й квота провайдера |
| Не відкрилася програма | Чи встановлена вона та чи є правильний запис/псевдонім у каталозі |
| Вебпошук не знайшов сторінку | Уточніть запит; індексація, антибот-захист і доступність сайту обмежують результати |

Почніть з `main.py --doctor` і журналу останньої сесії.
`main.py --audio-test` — **окрема перевірка із записом мікрофона**, запускайте свідомо.
`main.py --diagnostics` готує діагностичні матеріали; перегляньте їх перед передаванням.
Журнал сесії може містити особисту розмову — не публікуйте його без очищення.

## 9. Приватність і безпека

- API-ключі, паролі та recovery key не вводьте в чат і не додавайте в Git.
- `.env` і зашифроване сховище `data/secrets.json` — **різні механізми**:
  виключення файла з Git не є його шифруванням.
- Після налаштування перенесіть `RECOVERY_KEY.txt` на захищений носій
  та приберіть локальну копію, переконавшись, що ключ збережений.
- UI слухає лише `127.0.0.1`; посилання містить доступ до поточної сесії.
  Не публікуйте його й не відкривайте сервер напряму в інтернет.
- Голосові підтвердження не є біометричною ідентифікацією користувача.
- Звичайний локальний STT не означає, що текст не піде хмарному LLM.
- Не запускайте асистента з правами адміністратора без окремої потреби.

[Правила безпечної публікації](docs/PUBLICATION.md).

## 10. Оновлення та перенесення

Зупиніть ValleRa. Перевірте власні зміни перед оновленням:

```powershell
git status
git pull --ff-only
.\.venv\Scripts\python.exe install.py --profile desktop
```

Якщо Git повідомляє про конфлікти, спершу збережіть та узгодьте свої зміни;
не використовуйте `reset --hard` для обходу проблеми.

На іншому ПК клонуйте репозиторій і створіть нове `.venv`.
Git не переносить ключі, локальну конфігурацію, історію, моделі та приватні журнали.
Перенесення потрібних особистих даних виконуйте окремо й безпечно;
аудіопристрої виберіть заново.
[Покрокове встановлення та перенесення](docs/WINDOWS_SETUP.md).
