# Встановлення ValleRa на Windows

Повернутися до [README](../README.md). Усі команди виконуються в PowerShell
із кореня клонованого репозиторію, якщо не зазначено інше.

## 1. Передумови та клонування

Поточний орієнтир — Windows x64 і Python 3.12 x64. Встановіть
[Git](https://git-scm.com/downloads/win) та [Python](https://www.python.org/downloads/windows/)
із Python Launcher (`py`). Потрібні інтернет для пакетів/моделей і LLM API,
мікрофон та пристрій відтворення для голосового режиму. Дозвольте доступ
класичних програм до мікрофона в параметрах конфіденційності Windows.
Не запускайте асистента від адміністратора без окремої потреби.

У PowerShell перейдіть до каталогу, де зберігаєте проєкти:

```powershell
git clone https://github.com/Wuradzi/ValleRa.git
cd ValleRa
git --version
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe install.py --profile desktop
```

Наступні команди також виконуються з кореня `ValleRa`. Активація `.venv`
не обов’язкова: явний шлях до Python уникає проблем із PowerShell ExecutionPolicy.
Не копіюйте `.venv` з іншого комп’ютера. Інсталятор установлює Python-залежності,
але не встановлює голос RHVoice або системні CUDA-бібліотеки.

## 2. Голос відповідей — RHVoice

На [сторінці українських голосів RHVoice](https://rhvoice.org/uk-voices/)
оберіть **Volodymyr → Download the voice for other Windows programs**, не
NVDA-addon. Запустіть інсталятор голосу. За
[інструкцією RHVoice](https://rhvoice.org/installation/) цей SAPI 5 пакет уже
містить потрібний рушій. Перезапустіть ValleRa після встановлення.
Якщо встановили інший український голос, у майстрі введіть його назву замість
`Volodymyr`; параметр зберігається в `tts.voice_hint`.

## 3. Вибір STT перед завантаженням моделей

Створіть локальну конфігурацію, **не перезаписуючи наявну**:

```powershell
if (-not (Test-Path config.json)) { Copy-Item config.example.json config.json }
```

У `config.json` виберіть `stt.profile` (`auto` початково). Моделі в
`stt.profiles` — змінні кандидати, а не доведені переможці:

| Значення | Модель | Призначення |
|---|---|---|
| `quality` | faster-whisper `large-v3` | Якість; GPU або явно вибраний CPU |
| `balanced` | faster-whisper `small`, CPU/int8 | CPU-кандидат; medium/turbo теж доступні для порівняння |
| `edge` | sherpa-onnx multilingual Whisper small/int8 | Експериментальний ARM64/CPU-кандидат; не готовий голосовий режим |

Залиште `stt.backend: "auto"`, щоб backend задавав профіль, не прихований fallback.
Auto обирає balanced для звичайного x86 CPU, edge для ARM; quality — лише за
наявності CUDA й відомих RAM >=16 GiB та VRAM >=8 GiB. За невідомої VRAM
лишиться balanced; для GPU можна явно вибрати quality. Це обережні умови
вибору, не гарантії споживання пам’яті чи швидкості. Старі quality_profile та
low_resource підтримуються як legacy; новий profile має пріоритет.
**Edge поки benchmark-only за рівнем довіри:** ONNX API не дає каліброваної
confidence, тому runtime просить уточнення й не дозволяє ACTION.
`stt.primary_device: "auto"` у quality вибирає CUDA за доступності, інакше CPU/int8;
`"cpu"` явно вимикає GPU. Large-v3 потребує значного обсягу RAM/диска та може
бути повільною на CPU. Точні вимоги й latency на вашому ПК ще треба виміряти.
Balanced/edge не потребують CUDA. Не плутайте `stt.profile` з `performance.profile`: `--profile fast`
не перемикає primary-модель на меншу. Старий `stt.whisper.model` її теж не обирає.

Для CUDA потрібні сумісна NVIDIA GPU, драйвер і бібліотеки з
[офіційних вимог faster-whisper](https://github.com/SYSTRAN/faster-whisper#gpu):
на дату перевірки 03.10.2026 — cuBLAS для CUDA 12 та cuDNN 9 для CUDA 12.
Установіть їх за інструкціями виробника та забезпечте доступність DLL процесу
Python. Сам `pip install` цього не гарантує. За помилки GPU ValleRa пробує
ту саму модель на CPU й записує причину в лог; це може значно сповільнити роботу.

Завантажте обидві потрібні моделі:

```powershell
.\.venv\Scripts\python.exe tools\download_vosk_model.py
.\.venv\Scripts\python.exe tools\download_whisper_model.py
```

Vosk потрібен для голосових підтверджень навіть із primary faster-whisper.
Другий скрипт завантажує **вибраний STT-профіль**, потім пробує завантажити модель
в пам’ять. Це може тривати довго. Після зміни профілю повторіть цю команду.
Звичайний запуск за замовчуванням не скачує відсутню модель
(`primary_local_files_only: true`) і не підміняє її Vosk
(`fallback_backend: "none"`). Повідомлення про відсутню модель — не готовий STT.

## 4. Майстер налаштування та перший запуск

```powershell
.\.venv\Scripts\python.exe main.py --setup --web-ui
```

Майстер запропонує мікрофон, пристрій відтворення, калібрування, TTS-голос,
API-ключі та майстер-пароль. Для розмови потрібен доступний налаштований LLM:
наприклад, ваш Gemini API-ключ; інші ключі можна залишити порожніми.
Ключі вводьте лише локально в приховані поля майстра. Вони зберігаються в `.env`,
а не в Git; це окремо від зашифрованого сховища `data/secrets.json`.
Перенесіть `RECOVERY_KEY.txt` на захищений носій та приберіть локальну копію.

`--setup` після майстра продовжує запуск застосунку, а не лише налаштовує його.
Майстер-пароль вводиться в терміналі. У вебінтерфейсі мікрофон початково
вимкнений — увімкніть його кнопкою після готовності STT. Запис ведеться на
комп’ютері, де запущено Python, а не на віддаленому пристрої браузера.
Завершення — Ctrl+C в терміналі. Для наступних запусків майстер не потрібен:

```powershell
.\.venv\Scripts\python.exe main.py --web-ui
```

Для перевірки діалогу без STT використовуйте `main.py --text-only --web-ui`.
Це вимикає голосове введення, але не є обіцянкою вимкнення TTS.

## Перевірка першого запуску

- Спочатку введіть коротку репліку текстом: перевірте відповідь LLM.
- Перевірте звучання відповіді й вибір українського голосу.
- Дочекайтеся готовності моделі в `logs/sessions/`, увімкніть мікрофон і скажіть
  коротку українську репліку. Перевірте розпізнаний текст.
- Для перевірки підтвердження попросіть відкрити браузер і відмовтеся голосом
  «ні»: дія не повинна виконатися. Це ручна перевірка, не автоматичний тест.

| Проблема | Що перевірити |
|---|---|
| `py` або Python 3.12 не знайдено | Установку Python Launcher; відкрийте новий PowerShell |
| Немає моделі / природне мовлення не розпізнається | Профіль у config.json, завершення download helper, журнал STT |
| CUDA/DLL error або дуже повільний STT | Фактичний device і fallback reason у журналі; для діагностики виберіть `primary_device: "cpu"` |
| Не чує мікрофон | Дозвіл Windows, кнопку UI, пристрій; повторіть `--setup` для нового аудіопристрою |
| Не озвучує / інший голос | SAPI-версію RHVoice, `tts.voice_hint`, output device і гучність |
| LLM недоступний / 429 | Локальний API-ключ, доступність вибраної моделі, квоту; це не помилка STT |

Регресійні тести не використовують живий мікрофон або LLM API:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tester.py --all --verbose
.\.venv\Scripts\python.exe -m ruff check .
git diff --check
```

Ці перевірки не доводять якість голосу або швидкість на новому ПК. Живі probes
запускаються окремо через `tester.py` та можуть витрачати API-квоту.
Звіти тестів: `logs/tests/`; журнали застосунку: `logs/sessions/`.
Перед передаванням журналу перевірте його: він містить текст розмови.

## Оновлення й перенесення на інший комп’ютер

Для вже клонованої копії, зупинивши застосунок:

```powershell
git status
git pull --ff-only
.\.venv\Scripts\python.exe install.py --profile desktop
```

Якщо є власні зміни або Git відмовляється оновлюватися, спочатку збережіть і
узгодьте їх; не застосовуйте `reset --hard` для обходу проблеми.
На чистому ПК натомість виконайте кроки 1–4. Git не переносить `.env`,
`config.json`, сховище/пам’ять у `data`, кеш, журнали, моделі та `.venv`.
Перенесення особистих даних — окрема захищена операція, не публічний коміт.
На новому ПК заново виберіть аудіопристрої: їхні індекси можуть відрізнятися.
