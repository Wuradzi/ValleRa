# Безпечна публікація ValleRa

Публічний репозиторій містить код, тести, ресурси інтерфейсу й шаблони
налаштувань. `.env.example` має порожні поля ключів; власні ключі задавайте
тільки локально. `config.json` створюється локально з прикладу/майстра.

Не публікуються `.env`, особистий config, ключ відновлення, `data`, `logs`,
`cache`, `models`, записи голосу, налаштування IDE та приватна документація.
Деякі посилання README ведуть на локальні журнали/звіти дослідження, яких
немає в публічній копії. Це не файли, потрібні для запуску застосунку.
Їх публікація потребує окремого знеособлення та згоди власника даних.

Перед кожним комітом:

1. Перегляньте `git status --short`, додавайте лише конкретні перевірені файли.
2. Перегляньте `git diff --cached --stat` та `git diff --cached` локально.
3. Перевірте staged-вміст на ключі, паролі, приватні діалоги, записи та особисті
   шляхи. Не вставляйте необроблений diff чи результати пошуку секретів у чат.
4. Переконайтеся, що автор коміту має вашу GitHub noreply-адресу.
5. Для перевірок програми використовуйте `python tester.py --all`.
6. Коміт і push — окремі операції. Не використовуйте примусовий push без
   погодженого плану й резервної копії історії.

`.gitignore` не захищає файли, вже додані в Git, і не очищає старі коміти.
Якщо секрет уже опублікований, спочатку відкличте/замініть його. Подальше
очищення історії не може відкликати чужі клони чи завантажені копії.
Нове сканування не гарантує відсутності всіх можливих секретів; перевірка
має поєднувати шаблони, відомі локальні значення та ручний перегляд.
