# Технічне завдання на розроблення ValleRa Voice Assistant

Це опис вимог, не підтвердження реалізації кожної можливості. Вимоги змінювалися
під час розробки; актуальні статуси див. у [роадмапі](ASSISTANT_ROADMAP.md),
походження рішень і результати перевірок — у [журналі](DEVELOPMENT_LOG.md).

## 1. Загальний опис

**Назва:** ValleRa  
**Тип:** локальний голосовий асистент з інтеграцією LLM  
**Основна ОС першого етапу:** Windows  
**Подальша ОС:** Linux  
**Мова інтерфейсу:** українська  
**Мова розроблення:** Python 3.11–3.12  
**Ліцензія:** MIT  
**Поширення:** GitHub  
**Запуск MVP:** `python main.py`

ValleRa надає голосовий і текстовий інтерфейс для керування операційною системою, застосунками, вікнами, файлами, пам’яттю, нотатками, нагадуваннями, вебпошуком та контекстним діалогом.

Платний або ключовий API використовується лише для LLM. STT, TTS, OCR, пам’ять і системні дії виконуються локально.

## 2. Цільове обладнання

- ноутбуки приблизно від 2015 року;
- робота без обов’язкової дискретної відеокарти;
- пріоритет швидкості STT;
- локальні LLM можуть бути повільними на слабкому обладнанні.

## 3. Стек

- STT: гібрид Vosk + faster-whisper;
- TTS: RHVoice/Windows SAPI;
- нечіткий збіг: RapidFuzz;
- LLM: Gemini, Groq, OpenAI, Anthropic, Ollama;
- пошук: DDGS;
- погода: wttr.in;
- OCR: Tesseract;
- автоматизація: pyautogui, PyGetWindow, psutil;
- сховища: JSON/JSONL;
- шифрування: Fernet, PBKDF2HMAC;
- HTTP: httpx;
- асинхронність: asyncio.

## 4. Режими

### 4.1 Голосовий режим

Основний сценарій — безперервний покроковий діалог без слова активації. Після запуску
мікрофон автоматично приймає кожну завершену репліку, передає її в обробник і
повертається до прослуховування після відповіді. «Валера» є ім'ям асистента та
звичайною частиною тексту, а не сигналом активації.

Аудіо кожної репліки захоплюється один раз. Vosk визначає її межі, а
faster-whisper повторно транскрибує той самий PCM-буфер із параметром мови
`uk`, Silero VAD, контекстною підказкою та hotwords. Результат Whisper
приймається лише вище налаштованого порога впевненості. В іншому разі або за
помилки моделі використовується Vosk. Закриті граматики підтвердження не
запускають Whisper.

Звичайна фраза обробляється LLM. Локальна дія виконується лише після префікса:

> Команда: `<локальна команда>`

Після локальної дії звичайне спілкування продовжується. Окремий режим
«Душогуб» зберігає власний контекст до деактивації. Після запиту голосового
підтвердження відповідь приймається без додаткового префікса.

Команда миттєвої зупинки TTS:

> Команда: замовкни.

### 4.2 Текстовий режим

Доступний окремий `main_text.py` і текстове введення під час звичайного голосового запуску.

## 5. Обробка команд

Пріоритет:

1. явний префікс «Команда»;
2. службові команди й локальні навички;
3. програми й вікна;
4. файли;
5. пам’ять, нотатки, нагадування;
6. вебпошук;
7. фільтрація невідомої локальної команди без передачі до LLM;
8. звичайні фрази без префікса передаються лише до LLM.

Поріг нечіткого збігу навички: 85%. Поріг пошуку програми: 80%.

За низької впевненості STT команда відхиляється без пропозиції виконати розпізнаний шум.
Звичайна голосова репліка нижче `stt.chat_confidence_threshold` (типово 0.5)
також відхиляється до виклику LLM із локальним проханням повторити її.

## 6. LLM

Порядок:

1. Gemini;
2. Groq;
3. OpenAI;
4. Anthropic;
5. Ollama;
6. шаблонний режим.

На старті перевіряються налаштовані провайдери. Звичайний діалог і керований
розбір явних команд — окремі запити. З увімкненим `commands.llm_interpretation`
нерозпізнана команда може отримати один JSON-розбір без історії; локальний
виконавець перевіряє дозволену дію й параметри та запитує підтвердження.
Відомі команди й команди секретів залишаються локальними. Деталі та межі
першого етапу наведено в `docs/ASSISTANT_ROADMAP.md`.

Після перемикання повернення до Gemini відбувається лише після перезапуску.

Gemini відповідає потоково через async `generate_content_stream`. Завершені
фрази до 240 символів відразу передаються TTS; після отримання частини
відповіді повторні спроби вимкнено, щоб не озвучувати її двічі. Інші провайдери
поки використовують непотоковий fallback. Windows TTS має постійний SAPI-процес
і прямий стандартний аудіовихід без проміжного WAV. Конкретний вибраний
аудіопристрій використовує короткі WAV-фрази. Whisper ізольовано в процесі,
який завершується під час виходу; скасування не очікує завершення inference.

Команди погоди окремо розбирають місто й період (зараз, сьогодні, завтра),
отримують структуровані дані wttr.in та називають джерело. Загальний вебпошук
виводить до трьох посилань у консоль і стислий уривок першого результату
голосом, без LLM-переказу чи автоматичного відкриття сторінок.

Завантаження моделі Ollama виконується користувачем окремо через `ollama pull`;
startup ValleRa не блокується інтерактивним завантаженням або перевіркою
неналаштованого провайдера.

## 7. Пам’ять

Звичайні факти зберігаються у `memory.json`.

Запис містить:

- ID;
- ключ;
- значення;
- категорію;
- дату створення;
- дату оновлення;
- ознаку чутливості.

До LLM передаються тільки релевантні до теми нечутливі записи.

## 8. Секрети

Секрети зберігаються окремо від звичайної пам’яті.

- значення шифруються Fernet;
- data key обгортається ключем, отриманим з майстер-пароля;
- створюється окремий ключ відновлення;
- паролі не озвучуються;
- після підтвердження пароль копіюється у буфер;
- буфер очищується через 30 секунд;
- секрети не передаються LLM.

## 9. Нотатки

Запис містить:

- ID;
- назву;
- текст;
- категорію;
- теги;
- дату створення;
- дату оновлення;
- статус виконання.

Підтримуються створення, читання, пошук, редагування, завершення й видалення.

## 10. Нагадування

Підтримуються:

- одноразові;
- щоденні;
- щотижневі;
- інтервальні.

Пропущені нагадування повідомляються після запуску та мають статус `missed`, доки користувач не позначить їх виконаними.

## 11. Застосунки й вікна

Windows-індексація:

- Start Menu;
- робочий стіл;
- ручні записи.

Окремі команди:

- відкрити програму;
- закрити вікно;
- згорнути вікно;
- розгорнути вікно;
- завершити процес.

Примусове завершення потребує підтвердження.

## 12. Файли

Без підтвердження доступні користувацькі каталоги:

- Desktop;
- Documents;
- Downloads;
- Pictures;
- Videos;
- Music.

Системні каталоги потребують окремого дозволу. Видалення за замовчуванням виконується в кошик.

Пошук підтримує назву, розширення, дату зміни й розмір.

## 13. Підтвердження

Фраза:

> Підтвердіть операцію: `<тип операції>`.

Час: 15 секунд.

Приймаються:

- так;
- підтверджую;
- підтверджує;
- гаразд;
- добре;
- ні;
- скасувати.

Кожна небезпечна дія підтверджується окремо.

## 14. Дані й резервування

JSON зберігається:

1. у тимчасовий файл;
2. після перевірки валідності;
3. атомарною заміною;
4. з п’ятьма резервними копіями.

## 15. Логи й метрики

Кожна сесія `main.py` має окремий `logs/sessions/session-*.log` із
діагностикою, таймінгами, текстом діалогу й помилками. Приховане введення
паролів не журналюється; відомі секрети та типові записи облікових даних
маскуються. Журнал може містити приватну розмову: його слід перевіряти перед
передаванням іншим. Старі `valera.log*` збережено без змін.

`metrics.jsonl` містить:

- час;
- тип події;
- тип команди;
- час виконання;
- провайдер;
- статус успіху.

Підтримується голосова команда формування звіту.

## 16. Діагностика

```powershell
python main.py --diagnostics
```

Перевіряються:

- залежності;

- доступність faster-whisper;
- TTS;
- аудіо;
- Tesseract;
- LLM;
- доступ до сховищ.
